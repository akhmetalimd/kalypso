# KALYPSO — правила проекта

KALYPSO (KAzakhstan LYmphoma Patients Survival and Outcomes) — пробная платформа
регистра лимфопролиферативных заболеваний. Регистр — деперсонифицированный
исследовательский слой; his.kz — источник истины с персональными данными.
Между ними — граница деидентификации. Требования — PRD v1.0 (у владельца проекта).

## Непреложные правила

1. **Только синтетика.** В репозитории, тестах, фикстурах, логах и примерах — только
   синтетические данные. Реальные данные пациентов не загружаются до соглашения об
   обработке данных и одобрения этического комитета.
2. **ИИН не хранится и не логируется.** В БД попадает только `iin_hash` =
   HMAC-SHA256(ИИН, ключ) в полном виде (64 hex). Сырой ИИН живёт только в памяти
   запроса: не пишется в БД, логи, аудит, сообщения об ошибках, кэш, URL.
3. **Хэш считается только на сервере** (или в коннекторе his.kz внутри сети клиники).
   Ключ HMAC никогда не попадает в браузер, репозиторий или облако: у ИИН низкая
   энтропия, с ключом все хэши восстанавливаются перебором. Ключ — из окружения
   (`KALYPSO_HMAC_KEY`), один на все филиалы, смена ключа = новая `hash_key_version`.
4. **Деидентификация до AI.** Во внешнюю модель уходит только деидентифицированный
   текст. Свободный текст (гистология, ПЭТ-КТ) проверяется на идентификаторы перед
   сохранением; БД дополнительно отвергает 12-значные числа в этих полях.
5. **Человек в контуре.** AI создаёт только предложения. В регистр попадает лишь то,
   что принял или исправил куратор; провенанс записи это отражает.
6. **Без жёсткого удаления.** Клинические записи удаляются мягко (`deleted_at`);
   роль приложения не имеет DELETE на клинических таблицах.
7. **Аудит — на триггерах БД.** Приложение в каждой транзакции делает
   `SET LOCAL app.user_id = '<uuid>'` (и `app.change_reason` при пересмотре диагноза).
   `audit_log` и `diagnosis_version` неизменяемы.

## Схема данных

- `schema.sql` — нормативный baseline, **не редактируется**. Все изменения — новыми
  файлами в `db/migrations/` (порядковый номер + суть). Применение: `psql -1 -f <файл>`.
- В БД хранятся **коды**, а не русские подписи (`alive`, `death`, `M`…). Подписи на
  русском/казахском — в слое локализации. Названия систем и критериев (`Rai`, `Binet`,
  `iwCLL 2018`) остаются как есть.
- Провенанс у каждой записи: `source` (`his_structured` / `ai_document` / `manual`)
  + `provenance` (`retrospective` / `prospective`).
- Пропуск «условного» поля — код пропуска (`patient_missing`, `module_data.missing`),
  а не пустая ячейка.
- Нозологии — дерево WHO-HAEM5 в `config/nosology_tree.json`; модульные поля — EAV
  (`module_data`), без ALTER TABLE на каждую нозологию.

## Движок

- `registry_core.py` — без внешних зависимостей; логика, одинаковая на любой платформе.
  Самотест: `python registry_core.py`. Менять сигнатуры существующих функций нельзя,
  только добавлять новые.
- Log-rank и Cox в платформе не считаются — только на выгрузке (lifelines / R).
  Пороги для «Исследователя выживаемости» — внешние, не подбираются по этим же данным.

## Окружение

- Python 3.12, PostgreSQL 16 (минимум 15 — нужен `NULLS NOT DISTINCT`).
- Интерфейс — русский, строки через слой локализации (готовность к казахскому).
