# KALYPSO

**KA**zakhstan **LY**mphoma **P**atients **S**urvival and **O**utcomes — пробная платформа регистра
лимфопролиферативных заболеваний: ручной ввод по 16 нозологиям (WHO-HAEM5), карточка пациента с
полнотой и контролем качества, роли и филиалы, аудит, дашборды, «Исследователь выживаемости»
(Каплан–Майер), документы по шаблонам, деидентифицированная выгрузка.

> **Только синтетические данные.** Пилот работает на сгенерированных пациентах. Реальные данные
> пациентов в платформу не вносить — до соглашения об обработке данных и одобрения этического комитета.

Created by Aidos Akhmetali and the Lymphoma Working Group · Version 0.1

## Быстрый старт: запустить у себя

Нужно:
- **Python 3.12 или новее** (64-битный) — [python.org/downloads](https://www.python.org/downloads/).
  На Windows при установке отметьте **«Add python.exe to PATH»**.
- **Git** — [git-scm.com](https://git-scm.com/downloads) (или скачайте архив, см. ниже).
- Windows 10/11, macOS или Linux; около 1 ГБ места; интернет — только для первой установки.

PostgreSQL ставить не нужно: встроенный PostgreSQL 16 поднимается сам (пакет `pgserver`).

### 1. Скачать код

```bash
git clone https://github.com/akhmetalimd/kalypso.git
```

На Windows клонируйте в папку с коротким путём — например, в `C:\` (получится `C:\kalypso`).

Без Git: на странице репозитория **Code → Download ZIP**, затем распакуйте архив.

### 2. Запустить

**Windows** — откройте папку `kalypso` и дважды щёлкните **`start.bat`**
(или в командной строке):

```bash
cd kalypso && start.bat
```

**macOS / Linux:**

```bash
cd kalypso && ./start.sh
```

Скрипт при первом запуске создаёт окружение Python (`.venv`), ставит зависимости, поднимает
встроенную базу, применяет миграции и создаёт синтетическую когорту (около 1 160 пациентов
по 16 нозологиям). **Первый запуск — 3–10 минут**, следующие — несколько секунд.

### 3. Открыть

Когда в окне появится `Uvicorn running on http://127.0.0.1:8765`, откройте в браузере
**http://127.0.0.1:8765**.

Это демо-режим пробной версии: вход без пароля, **роль переключается в шапке** (лечащий врач
филиала A/B/C, куратор, аналитик, администратор). Права, разграничение по филиалам и аудит — как при
обычном входе: врач видит только пациентов своего филиала, ИИН — только врач своего филиала и куратор.

Остановить — **Ctrl+C** в окне скрипта. Данные сохраняются в папке `.devdb/`; удалить её —
начать с чистой синтетики.

### Если что-то не так

| Симптом | Что сделать |
|---|---|
| `python` не найден | Установите Python 3.12+ с «Add python.exe to PATH» и откройте новое окно. На macOS/Linux можно указать интерпретатор: `PYTHON=python3.12 ./start.sh` |
| Порт 8765 занят | Другой порт: `set PORT=9000` и `start.bat` (Windows) или `PORT=9000 ./start.sh` |
| «PostgreSQL восстанавливается после аварийной остановки» | Скрипт подождёт и повторит попытку сам (до минуты). Если не помогло — закройте все окна платформы и запустите снова |
| Windows: «Слишком длинный путь» или `No such file or directory … pgserver …` при установке | Переложите папку проекта ближе к корню диска, например `C:\kalypso`, удалите `.venv` и запустите снова (у встроенного PostgreSQL глубокие пути, а Windows по умолчанию ограничивает их 260 символами) |
| Ошибка при установке зависимостей | Удалите папку `.venv` и запустите скрипт ещё раз (нужен интернет) |
| Linux: PostgreSQL не стартует под root | Запускайте от обычного пользователя |

### Вручную, без скрипта

```bash
python -m venv .venv
```

```bash
.venv/Scripts/python -m pip install -r requirements-dev.txt
```

```bash
.venv/Scripts/python -X utf8 -m kalypso.dev
```

На macOS/Linux вместо `.venv/Scripts/python` — `.venv/bin/python`.

### Тесты

```bash
.venv/Scripts/python -X utf8 -m pytest
```

Около 580 тестов, 10–15 минут: каждый тест получает свою копию базы во встроенном PostgreSQL.

## Развёртывание на сервере

Для пилота на сервере клиники — Docker Compose (PostgreSQL 16 + приложение + nginx/HTTPS), роли БД,
резервные копии: инструкция для ИТ-службы — [`docs/deploy.md`](docs/deploy.md).

## Что внутри

| Путь | Что это |
|---|---|
| `kalypso/` | Платформа: сервисы регистра (`registry.py` — единственный путь записи), роли и вход, аналитика и графики, документы, выгрузка, веб-интерфейс (`web/`: FastAPI + Jinja2, без обязательного JavaScript). |
| `schema.sql`, `db/migrations/` | Схема PostgreSQL и миграции: ядро данных, коды пропусков, провенанс, аудит на триггерах, RLS по филиалам (второй рубеж доступа), проверки индексов и критериев ответа по нозологиям. |
| `config/` | Дерево нозологий WHO-HAEM5 (стадии, индексы, критерии ответа, поля модулей, режимы и их классы), лабораторные единицы (LOINC/UCUM), исследования карточки, роли. |
| `registry_core.py` | Движок без внешних зависимостей: конечные точки (OS, PFS, EFS, TTNT…), Каплан–Майер с ДИ, индексы, канонизация анализов, проверки. Самотест: `python registry_core.py`. |
| `tests/` | Тесты: БД и RLS, сервисы, веб, аналитика, все 16 нозологий. |
| `deploy/`, `docs/` | Развёртывание пилота и инструкции. |
| `CLAUDE.md` | Правила проекта и устройство кода. |
| `app.py` | Ранний референс-API (SQLite, старые ключи) — сохранён как образец, не используется. |

## Принципы, зашитые в код

- **Расширяемость** — дерево нозологий и config-таблица показателей: расширение = запись в конфиге, без изменения схемы (для модулей — EAV-таблица `module_data`).
- **Амбиспективность** — коды пропусков (`patient_missing`) и `provenance` на каждой записи (ретро/проспективно — автоматически по дате начала регистра); исходные лабораторные значения не затираются (`value_raw` + `value_canonical`).
- **Сопоставимость** — ИИН как ключ автодедупликации между филиалами (на раннем этапе хранится открыто, виден только врачу своего филиала и куратору); каноническая единица на показатель.
- **Гранулярность события** — `event_type` включает «старт новой линии» и `death_cause`, чтобы собирать PFS / modified PFS / EFS / TTNT как запрос, а не как поле.

## Совместимость с OMOP

Для внешних коллабораций и пулинга (как в HARMONY) ядро маппится на OMOP CDM:
`patient` → PERSON/OBSERVATION_PERIOD; `who_haem5`/`icd_o_3_2` → CONDITION_OCCURRENCE
(через словари SNOMED/ICD-O); `lab` → MEASUREMENT (LOINC + UCUM уже готовы);
`therapy_line` → DRUG_ERA/DRUG_EXPOSURE. Канонические единицы и LOINC делают этот
маппинг механическим.

## Статистика

`registry_core` даёт Каплан–Майер и медианы (для дашборда и «Исследователя»). **Log-rank и
регрессия Кокса — на выгрузке** (lifelines / R): наблюдательные ассоциации требуют
поправки на риск и внешнего порога, а не подгонки по своим же данным. Сравнение режимов
терапии — только описательное, с предупреждением о смещении по показаниям.

Картина на главной — Арнольд Бёклин, «Одиссей и Калипсо» (1882), общественное достояние
(`kalypso/web/static/img/SOURCES.md`).
