# KALYPSO ↔ his.kz: вопросы поставщику МИС (для этапа П5)

Регистр KALYPSO — деперсонифицированный исследовательский слой. Данные МИС забирает
коннектор на сервере **внутри сети клиники**, хэширует ИИН (HMAC), отбрасывает всё
вне белого списка полей и передаёт в регистр только после решения куратора.
Готово (П4): интерфейс адаптера, конвейер приёма, маппинг полей как конфиг
(`config/field_mapping/his_kz.json`, пути полей — заглушки), экран куратора.
Ответы ниже нужны, чтобы реализовать `HisKzAdapter` и заполнить маппинг.

## 1. Протокол и доступ
1. Какой интерфейс доступен: REST/JSON, HL7 FHIR (версия R4?), HL7 v2, SOAP, выгрузка файлов?
2. Есть ли тестовый контур с синтетическими данными и его адрес?
3. Авторизация: OAuth2 (какой поток), сертификаты (ГОСТ / RSA, NCALayer), IP-фильтр, VPN?
4. Учётная запись для системной интеграции: кто выдаёт, какие права (только чтение, ограничение по учреждению)?
5. Лимиты запросов, окна обслуживания, требования к частоте опроса.

## 2. Данные и эндпоинты
6. Поиск пациентов по диагнозу: можно ли получить всех пациентов с кодами МКБ-10 C91.1 и C83.0
   (пилот), без выгрузки остальных?
7. Лента изменений: есть ли «изменено с момента T» для пациентов, диагнозов, анализов, документов?
   Как обрабатываются удаления и исправления записей?
8. Постраничная выдача: формат курсора/страниц, максимальный размер страницы.
9. Пациент: поля пола, даты рождения, учреждения (код), даты последнего визита; где ИИН.
10. Диагнозы: версия МКБ (10 / 11), дата установления, признак основного/сопутствующего, история изменений.
11. Лабораторные: локальные коды показателей — есть ли соответствие LOINC; единицы измерения
    (как записываются: «г/л», «10^9/л»…); референсные значения; дата забора и дата результата.
12. Документы: какие типы есть (гистология, ИГХ, FISH, молекулярные, ПЭТ-КТ, выписки), формат
    (текст, PDF с текстом, скан), кодировка, можно ли получить только текст заключения.
13. Уникальные идентификаторы записей: стабильны ли ID при исправлении записи?
14. Справочник учреждений (коды) и их соответствие филиалам.

## 3. Правовое и эксплуатационное
15. Соглашение об обработке данных: кто подписывает, какие требования к хранению и журналированию.
16. Требования к размещению коннектора (сервер в сети клиники, ОС, сеть, обновления).
17. Требования к журналам доступа на стороне МИС; кто контролирует.
18. Контакт технической поддержки и процесс согласования изменений схемы.

## Что уже учтено в архитектуре
- ИИН не хранится: в регистр уходит только HMAC; внешние ID записей МИС — тоже только HMAC.
- Белый список: поля, не описанные в маппинге (ФИО, адрес, телефон, полис…), отбрасываются до записи.
- Свободный текст очищается от идентификаторов; в AI документ уходит только после проверки куратором.
- Изменение схемы МИС = правка конфига маппинга, не кода; неизвестный код попадает куратору как проблема.
- Инкрементальная подгрузка пакетом (раз в сутки/неделю), сбой одной записи не прерывает прогон.
